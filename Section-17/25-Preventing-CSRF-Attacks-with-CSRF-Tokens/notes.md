# 🛡️ Preventing CSRF Attacks with CSRF Tokens

### 📌 What is a CSRF Token?

A **CSRF Token** is a **random, unpredictable value** generated by the server and used to verify that a request actually came from the legitimate application.

The attacker does not know the valid token, so their forged request is rejected.

---

### 🔹 How CSRF Token Works

**1. Server generates a token**

```text
csrfToken = "random-secret-value"
```

**2. Server sends the token to the legitimate client**

For example, inside a form:

```html
<input type="hidden" name="csrfToken" value="random-secret-value" />
```

**3. User submits the form**

The token is sent along with the request:

```http
POST /transfer
csrfToken=random-secret-value
```

**4. Server validates the token**

```text
Valid token   → Process request
Invalid/missing token → Reject request
```

---

### 🔹 Why Does It Prevent CSRF?

The attacker can make the victim's browser send a request, but generally **cannot read the legitimate website's CSRF token** because of the browser's same-origin restrictions.

So the attacker can send:

```http
POST /transfer
amount=10000
```

but cannot provide the correct:

```text
csrfToken=random-secret-value
```

Therefore, the server rejects the request.

---

### 🔹 CSRF Token Flow

```text
User → Legitimate Website
          ↓
      Generate Token
          ↓
      Send Token
          ↓
User submits request
          ↓
Request + CSRF Token
          ↓
      Server validates
       ↙           ↘
    Valid         Invalid
      ↓              ↓
   Process         Reject
```

---

### 🛡️ Important Points

- Token should be **random and unpredictable**.
- Server must **validate the token** for state-changing requests.
- Never use predictable values such as:

  ```text
  12345
  username
  timestamp
  ```

- Commonly protect:
  - `POST`
  - `PUT`
  - `PATCH`
  - `DELETE`

- CSRF protection is especially important for **cookie-based authentication**.

### 🧠 Remember

> **CSRF Token = Secret value that proves the request came from the legitimate application.**

**Attacker can send the request ❌
Attacker cannot provide the valid token ❌
Server rejects the forged request ✅**

### 🎤 Interview Point

**Q: How does a CSRF token prevent CSRF attacks?**

**A:** A CSRF token is a random, unpredictable value generated by the server and included in legitimate requests. The server validates the token before processing sensitive actions. Since an attacker generally cannot obtain the valid token, forged cross-site requests are rejected.
